# Contributing to OpenField 🌿

Thank you for your interest in contributing to **OpenField**! 

OpenField is an open-source, **100% offline-first Android AI companion** designed to ensure that Capable, helpful, and private AI assistance is accessible anywhere on Earth—regardless of internet access, cellular dead zones, or subscription barriers.

Whether you are fixing a small bug, writing a new Knowledge Pack guide, optimizing on-device inference, or polishing Jetpack Compose animations, your contributions make a profound difference to users worldwide.

---

## 🧭 The OpenField Constitution (Non-Negotiable Principles)

Before proposing or implementing changes, please internalize our foundational project rules:

1. **Offline-First by Design:**  
   Every core feature (Chat, Document Q&A, Image Understanding, Problem Solving, Learning, Tools) **must function completely when the device is in airplane mode**. Never introduce mandatory cloud dependencies.
2. **Zero Cloud Inference & Zero Telemetry:**  
   All AI reasoning runs strictly on-device using **Gemma 4 E2B IT** via **Google LiteRT-LM**. Never silently transmit user prompts, documents, images, audio, or private files to a remote server.
3. **No Fake AI:**  
   Never ship simulated model output, canned success responses, or hardcoded answers that pretend to be generated by AI. Errors must be clearly communicated as system messages.
4. **Honest Capability & Evidence Retention:**  
   When retrieving from personal documents or knowledge packs, the system must retain and cite exact source chunks and page numbers. If evidence is insufficient, the system must transparently disclose that fact.
5. **Preserve User Data & Safety:**  
   Room SQLite and app-private storage are the sources of record. Never execute destructive operations or delete user files without explicit, confirmed user consent.

## 🗺️ How You Can Contribute

You don't need to be an Android core developer to contribute to OpenField. We warmly welcome contributions across multiple disciplines:

### 1. 📚 Authoring & Curating Knowledge Packs
Help expand OpenField's offline knowledge repository! You can author authentic, high-quality technical guides in Markdown:
- **Topics needed:** Emergency First Aid, Automotive Diagnostics, Solar & Off-Grid Electrical Systems, Water Purification, Agriculture/Soil Science, Mathematics, Woodworking, and Programming languages.
- *Rule:* Content must be authentic, factual, and strictly educational—zero generic filler text.
- See the [Knowledge Pack Authoring Guide](#-authoring-knowledge-packs) below.

### 2. 💻 Android & Jetpack Compose Development
- Enhance UI/UX components using Material 3 design tokens and fluid animations.
- Improve state restoration across process death and configuration changes.
- Optimize Room database queries and SQLite FTS4 retrieval performance.

### 3. 🧠 On-Device AI & LiteRT-LM Runtime
- Optimize memory footprints for devices with 4 GB – 6 GB of RAM.
- Benchmark and tune CPU thread pools for prompt evaluation and generation.
- Assist with LiteRT GPU/NPU acceleration exploration.

### 4. 🌐 Internationalization & Localization
- Help translate UI strings, starter questions, and offline guides into Hindi, Spanish, French, German, Japanese, and other languages.

### 5. 🧪 Testing & Hardware Verification
- Test OpenField on different Android devices, chipsets (Snapdragon, MediaTek, Tensor, Exynos), and OS versions (Android 8.0 to Android 15).
- Report runtime memory consumption, thermal behavior, and tokens-per-second generation speeds.

## 🛠️ Local Development Setup

### Prerequisites
- **Operating System:** Windows, macOS, or Linux.
- **IDE:** Android Studio (Ladybug / Meerkat or newer recommended).
- **JDK:** Java 17 or Java 21 (Temurin / OpenJDK).
- **Android SDK:** Platform 35 (Android 15), Build-Tools 35.0.0.
- **Python (Optional for pack packaging):** Python 3.10+.

### Step-by-Step Setup:

1. **Fork & Clone the Repository:**
   ```bash
   git clone https://github.com/YOUR_USERNAME/openfield-ai.git
   cd openfield-ai
   ```

2. **Open the Project in Android Studio:**
   - In Android Studio, select **Open** and choose the `openfield-ai/android` directory.
   - Allow Gradle to sync dependencies.

3. **Verify the Build and Run Unit Tests:**
   Open a terminal in the `android/` directory and run:
   ```bash
   # Windows PowerShell:
   .\gradlew.bat testDebugUnitTest

   # macOS / Linux:
   ./gradlew testDebugUnitTest
   ```
   *(All 202 unit tests should pass)*

4. **Run Android Lint Static Analysis:**
   ```bash
   # Windows PowerShell:
   .\gradlew.bat lintDebug

   # macOS / Linux:
   ./gradlew lintDebug
   ```

5. **Assemble Debug or Release APK:**
   ```bash
   # Build debug APK:
   .\gradlew.bat :app:assembleDebug

   # Build release APK:
   .\gradlew.bat :app:assembleRelease
   ```

6. **Install on Device via ADB:**
   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

## 📦 Authoring Knowledge Packs

Knowledge Packs are offline `.zip` bundles containing a manifest, structured JSON articles, and raw markdown files.

### Pack Directory Structure:
```text
my_pack.zip
├── manifest.json       # Pack ID, title, description, category, version, topics
├── articles.json       # Structured array of articles for Room extraction
└── articles/           # Individual readable markdown files
    ├── article_1.md
    └── article_2.md
```

### Adding a New Pack:
1. Open [`scripts/package_knowledge_packs.py`](scripts/package_knowledge_packs.py).
2. Add your pack definition to the `PACKS` list with:
   - Unique `id` (e.g., `solar_energy`)
   - `title`, `description`, `category`, `version`
   - List of `topics`
   - High-quality `articles` with Markdown content and tags.
3. Run the packager script:
   ```bash
   python scripts/package_knowledge_packs.py
   ```
   This automatically validates the format, builds the `.zip` archive into `catalog/packs/`, and updates `catalog/packs.json` with the new SHA-256 integrity checksum.

## 📐 Coding Standards & Architecture Guidelines

To keep the codebase maintainable, secure, and clean:

### Jetpack Compose & UI
- **Single Source of Truth:** State flows down from ViewModels or Controllers via `StateFlow`; events flow up.
- **Theme Tokens:** Always use design tokens from `com.openfield.app.core.theme` (`OpenFieldPrimaryBlue`, `OpenFieldNavyText`, `OpenFieldBackground`, `CardShape`) rather than hardcoded hex colors or arbitrary paddings.
- **Accessibility:** Provide meaningful `contentDescription` for all interactive icon buttons.

### Coroutines & Concurrency
- **No Blocking Operations:** Never run disk I/O, database queries, or PDF extraction on `Dispatchers.Main`.
- **Use the Right Dispatcher:**
  - `Dispatchers.IO`: File reads, Room database queries, ZIP extraction.
  - `Dispatchers.Default`: Parsing large JSON strings, image transformations, complex math computations.
  - `Dispatchers.Main`: UI state changes only.
- **Cooperative Cancellation:** Check `ensureActive()` or handle `CancellationException` in heavy loops.

### Room Database & Schema Migrations
- Increment `version` in `OpenFieldDatabase.kt` whenever changing entities.
- Always provide an explicit `Migration(start, end)` object.
- **Never use `fallbackToDestructiveMigration()` in production releases** to protect user data.

## 🏷️ Commit Message Convention

We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification:

| Prefix | Purpose | Example |
|---|---|---|
| `feat:` | A new feature or user-facing enhancement | `feat(chat): add share action to assistant message bubble` |
| `fix:` | A bug fix or defect correction | `fix(tools): resolve NewApi error in unit converter dropdown` |
| `docs:` | Documentation changes only | `docs: add architecture diagram and contributing guide` |
| `test:` | Adding or updating unit/instrumentation tests | `test(library): add SavedAnswerLifecycleTest suite` |
| `refactor:`| Code refactoring without changing behavior | `refactor(document): simplify PDF text extraction flow` |
| `perf:` | Performance optimization | `perf(search): optimize SQLite FTS4 query execution` |
| `ci:` | CI/CD pipeline or build script updates | `ci(github): add automated release workflow for tags` |

## 🚀 Pull Request (PR) Submission Checklist

Before submitting a Pull Request, please ensure:

- [ ] The code compiles without errors (`.\gradlew.bat assembleDebug`).
- [ ] All unit tests pass cleanly (`.\gradlew.bat testDebugUnitTest`).
- [ ] Android Lint passes with 0 errors (`.\gradlew.bat lintDebug`).
- [ ] No personal tokens, API keys, or private files are included.
- [ ] PR description clearly states **what was changed**, **why**, and **how it was verified**.
- [ ] For UI changes, attach screenshots or a screen recording (before vs. after).
- [ ] Verified that the feature operates properly in **airplane mode**.
